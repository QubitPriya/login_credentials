# Code Structure Explained

**Backend Only: Node.js + Express + MongoDB**

This is a pure backend API. No frontend code included.

## File Breakdown

### 1. server.js - The Main File
This is the entry point of the application.

```javascript
require('dotenv').config();           // Load .env file
const express = require('express');   // Import Express
const cors = require('cors');         // Import CORS
const connectDB = require('./config/db');  // Import DB connection
const userRoutes = require('./routes/userRoutes');  // Import routes

const app = express();                // Create Express app

// Connect to MongoDB
connectDB();

// Middleware - Process requests before they reach routes
app.use(cors());                      // Allow cross-origin requests
app.use(express.json());              // Parse JSON data

// Routes - Define API endpoints
app.use('/api/users', userRoutes);    // Use user routes

// Health check
app.get('/api/health', (req, res) => {
  res.json({ status: 'Server is running' });
});

// Start server on port 5000
const PORT = process.env.PORT || 5000;
app.listen(PORT, () => {
  console.log(`Server is running on port ${PORT}`);
});
```

**What happens:**
1. Loads environment variables from .env
2. Creates an Express server
3. Connects to MongoDB
4. Sets up middleware to handle requests
5. Defines routes (endpoints)
6. Starts listening on port 5000

### 2. config/db.js - Database Connection
This file handles connecting to MongoDB.

```javascript
const mongoose = require('mongoose');

const connectDB = async () => {        // Async function to connect
  try {
    // Connect to MongoDB using connection string
    const conn = await mongoose.connect(process.env.MONGODB_URI);
    console.log(`MongoDB Connected: ${conn.connection.host}`);
    return conn;
  } catch (error) {
    // If connection fails, show error
    console.error(`Error: ${error.message}`);
    process.exit(1);  // Stop the server
  }
};

module.exports = connectDB;
```

**What happens:**
1. Takes the MONGODB_URI from .env file
2. Tries to connect to MongoDB
3. If successful: prints connection success message
4. If failed: prints error and stops server

### 3. models/User.js - Data Structure (Schema)
This defines how user data is organized in MongoDB.

```javascript
const mongoose = require('mongoose');

// Define the schema (structure of data)
const userSchema = new mongoose.Schema(
  {
    firstName: {
      type: String,           // Must be text
      required: true,         // Required field
      trim: true              // Remove extra spaces
    },
    lastName: {
      type: String,
      required: true,
      trim: true
    },
    dateOfBirth: {
      type: Date,             // Must be date format
      required: true
    },
    gender: {
      type: String,
      enum: ['Male', 'Female', 'Other'],  // Only these 3 values allowed
      required: true
    }
  },
  {
    timestamps: true          // Auto add createdAt and updatedAt
  }
);

// Create and export the model
const User = mongoose.model('User', userSchema);
module.exports = User;
```

**What it defines:**
- `firstName` - Text, required
- `lastName` - Text, required
- `dateOfBirth` - Date, required
- `gender` - Must be one of: Male, Female, Other
- `createdAt` - Auto-generated timestamp
- `updatedAt` - Auto-generated timestamp
- `_id` - Unique identifier (auto-generated by MongoDB)

### 4. routes/userRoutes.js - API Endpoints
This file defines what the API can do.

```javascript
const express = require('express');
const User = require('../models/User');

const router = express.Router();  // Create router

// POST /api/users/submit-onboarding
router.post('/submit-onboarding', async (req, res) => {
  try {
    // Get data from request body
    const { firstName, lastName, dateOfBirth, gender } = req.body;

    // Validate - Check if all fields are provided
    if (!firstName || !lastName || !dateOfBirth || !gender) {
      return res.status(400).json({
        success: false,
        message: 'All fields are required'
      });
    }

    // Create new user document
    const newUser = new User({
      firstName,
      lastName,
      dateOfBirth,
      gender
    });

    // Save to database
    const savedUser = await newUser.save();

    // Send success response
    res.status(201).json({
      success: true,
      message: 'User onboarding data saved successfully',
      data: savedUser
    });
  } catch (error) {
    // Handle errors
    console.error('Error saving user:', error);
    res.status(500).json({
      success: false,
      message: 'Error saving user data',
      error: error.message
    });
  }
});

module.exports = router;
```

**What it does:**
1. **Receives** POST request with user data
2. **Validates** that all required fields are present
3. **Creates** a new User document
4. **Saves** it to MongoDB database
5. **Responds** with success or error message

## Request Flow (How Data Moves)

### When someone submits the form:

```
1. Frontend sends POST request
   ↓
2. Server receives at /api/users/submit-onboarding
   ↓
3. Express middleware processes (CORS, JSON parsing)
   ↓
4. Router function handles the request
   ↓
5. Validation checks if all fields exist
   ↓
6. Create new User object with data
   ↓
7. Mongoose saves to MongoDB
   ↓
8. Get confirmation from MongoDB
   ↓
9. Send response back to frontend
   ↓
10. Frontend receives success message
```

## Middleware Explained

**Middleware** = Functions that process requests before they reach the route handler

```javascript
app.use(cors());           // Allow requests from different domains
app.use(express.json());   // Parse incoming JSON data
```

**Example without middleware:**
- Request body would be raw text, hard to use

**Example with middleware:**
- Request body automatically converted to JavaScript object
- Easy to access data: `req.body.firstName`

## Error Handling

The API handles errors gracefully:

```javascript
try {
  // Try to save user
  const savedUser = await newUser.save();
  // Send success response
} catch (error) {
  // If error occurs, catch it
  console.log(error);  // Log error
  // Send error response
}
```

**HTTP Status Codes Used:**
- `200` - Success
- `201` - Created successfully
- `400` - Bad request (validation failed)
- `500` - Server error

## MongoDB Database Flow

```
1. API creates User object with data
   ↓
2. Validates against Schema (model/User.js)
   - Checks if firstName is string
   - Checks if gender is Male/Female/Other
   - Checks if all required fields present
   ↓
3. Saves to MongoDB collection called "users"
   ↓
4. MongoDB auto-generates:
   - _id (unique identifier)
   - createdAt (when created)
   - updatedAt (when last updated)
   ↓
5. Returns saved document to API
   ↓
6. API sends back to frontend
```
